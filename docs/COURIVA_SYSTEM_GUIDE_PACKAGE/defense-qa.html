1. What features do you have in your System that don't exist in the current System?

30-Second Spoken Answer: “Traditional cloud suites like Gmail or Outlook require constant internet and store organizational records on third-party servers, while basic local mail tools lack modern security and governance. Couriva combines a familiar modern webmail UI with 100% offline LAN sovereignty, Active Directory OU role gating (CourivaUsers & CourivaAdmins) with immutable objectGUID binding, privacy-isolated single-message spam review, instant session_epoch session revocation, and magic-byte finfo_file() attachment protection—with zero per-seat SaaS fees.”

2. Explain the ERD of your System (14 MariaDB InnoDB Tables)

30-Second Spoken Answer: “Our database uses 14 normalized InnoDB tables in MariaDB (webmail) with full ACID transactions, grouped into 4 clusters: Identity (users), Core Messaging & Threading (emails, email_recipients, attachments, scheduled_emails, delivery_status), Organization (folders, labels, email_labels, contacts, notifications), and Governance & Audit (blocked_senders, spam_reports, system_logs).”
  • Cluster 1 — Identity (users): Stores local & AD accounts (auth_source, immutable ad_object_guid), role, status, session_epoch, and must_change_password.
  • Cluster 2 — Messaging & Delivery: emails links 1:N from users (sender/recipient) and has a self-referencing FK (parent_email_id) for Reply/Forward threads plus category (Primary/Promotions/Updates). email_recipients handles To/Cc/Bcc (1:N); attachments stores file metadata (1:N); scheduled_emails & delivery_status track queued send and idempotent delivery.
  • Cluster 3 — Organization: User-owned folders (1:N), labels linked to emails via the M:N junction table email_labels, contacts, and notifications.
  • Cluster 4 — Governance & Audit: blocked_senders, spam_reports (isolated single-message reports), and system_logs. Foreign keys use ON DELETE SET NULL on sender/recipient references so audit history and snapshots remain intact.

Bonus Panelist Questions & Answers

Why did you build Couriva on PHP 8.2 + MariaDB + IIS 10 instead of cloud email or Node.js?

Our target environment is a closed organizational LAN running Windows Server 2022. IIS 10 + FastCGI PHP 8.2 + MariaDB 10.11 run natively on Windows Server with zero external internet or CDN dependencies, native OpenLDAP/LDAPS integration to Active Directory, and full ACID transactions.

How does Couriva prevent an attacker or admin from reading other users' private emails?

Every inbox, read, and attachment endpoint enforces strict recipient/sender ownership checks (cross-user attachment downloads return HTTP 403). Even when a user reports spam, admin/spam-reports.php exposes only that single reported message—never the user's mailbox.

What happens if Active Directory goes down—can the admin still log in?

Yes. Couriva supports a break-glass local administrator provisioned via CLI (php bin/create-admin.php) with auth_source='local'. LDAP_ALLOW_LOCAL_ADMIN_FALLBACK=true lets local admins sign in even when AD DS is unreachable, while normal AD users stay fail-closed.

How do password changes work for OU (Active Directory) users?

Passwords for AD users are managed in Windows Active Directory (Domain Controller ADUC / Set-ADAccountPassword / Ctrl+Alt+Del), not in Couriva's web UI. Because Couriva binds directly to AD over LDAPS on every login, password changes take effect immediately.

How did you separate normal users from administrators in Active Directory?

We scoped login to OU=CourivaUsers and created a dedicated sub-OU OU=CourivaAdmins inside it. On every sign-in, AuthService checks the user's Distinguished Name (DN): accounts in CourivaAdmins automatically receive role='admin', and moving them out reverts them to role='user'.

What bugs did your E2E testing find, and how did you fix them?

Our 2-pass browser E2E run (55 checks) uncovered 3 bugs—all fixed and re-verified: BUG-001 (duplicate CSP/security headers in web.config vs functions.php), BUG-002 (Primary/Promotions/Updates inbox tabs not filtering—fixed with migration 007_email_category.sql + classifier), and BUG-003 (axe-core accessibility contrast, aria-label, heading order, and <main> landmarks).
