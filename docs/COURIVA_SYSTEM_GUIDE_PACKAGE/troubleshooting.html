PART 10Troubleshooting and drift

10.1 Login loop / forced password change

Symptom: redirect to change-password.php on every route. Cause: must_change_password=1. Fix: complete the form (10+ chars, four classes) or reset via admin/edit-user.php. API 403 during this state is intentional.

10.2 500.0 FastCGI

Symptom: all .php return 500.0. Cause: PHP path mismatch. Fix: register C:\PHP\php-cgi.exe globally and align web.config:29.

10.3 404.8 on docs/ or storage/

Expected hardening. Use the filesystem (dir) or the guide figures, not HTTP, to inspect those paths.

10.4 Duplicate CSP / blocked inline scripts

Two CSP headers are present live: static from web.config:129 (no nonce) and dynamic from PHP (with nonce). Browsers intersect them, so nonce-bearing inline scripts can be blocked. Recorded as drift; do not claim a clean single header.

10.5 Scheduled mail not sending

Check schtasks /query /tn "Couriva-ScheduledMailProcessor" /v, storage\logs\, scheduled_emails.status, delivery_status.next_retry_at, and the 10-minute stale-job reclaim.

APPENDIX FJSON API & security controls

Every endpoint under public/api/ returns JSON, requires an authenticated session (401 if logged out), enforces require_api_password_change() (403 while must_change_password=1), and validates CSRF tokens on state-changing requests.

EndpointMethodPurpose
public/api/autosave_draft.phpPOSTSaves/updates draft content asynchronously every 30s during Compose.
public/api/batch_actions.phpPOSTBulk read/unread, star, archive/unarchive, snooze/unsnooze, move to folder/trash/spam, permanent delete.
public/api/contacts.phpGETReturns matching personal contacts for Compose To/Cc/Bcc autocomplete.
public/api/get_email.phpGETLoads a single email + attachments for the Inbox split reading pane.
public/api/organization.phpPOSTCreates, updates, or deletes user custom folders and color labels.
public/api/theme.phpPOSTPersists Light / Dark / System theme preference to users.
public/api/toggle_star.phpPOSTToggles starred state on a message row.

Core security controls active across all pages:

  • Closed identity: No public signup (register.php → 410), no web user creation (403), AD LDAPS :636 with immutable ad_object_guid, CLI-only break-glass admin.
  • Session & brute-force defense: session_regenerate_id(true), HttpOnly + SameSite=Strict cookies, session_epoch invalidation, IP throttle (10 fails / 15 min → 429).
  • Safe uploads & feedback: finfo_file() MIME verification, randomized filenames in non-web-reachable storage\attachments\ (404.8), unified accessible alerts via render_inline_alert().
